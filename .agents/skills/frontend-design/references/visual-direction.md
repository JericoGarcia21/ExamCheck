# Reference research and visual direction

Use for new interfaces or substantial visual redesigns. For a small change within an established product, use its existing design system and nearby screens as the primary reference.

## Inspect references with a purpose

Start with user-provided websites, screenshots, brand assets, and existing product screens. If no direction exists and browsing is available, inspect a small set of relevant real interfaces, usually two or three. Choose by audience, task, content density, and brand character; a visually impressive marketing page may be a poor reference for an operational dashboard.

Prefer actual product pages, official design systems, or inspectable screenshots over search snippets. Record the source URL or local asset, inspection date, screen or component examined, useful observation, and how it applies. Separate observed details from interpretation. If a source is inaccessible, say so; do not describe it as inspected. When browsing is unavailable, proceed with a clearly labeled proposed direction grounded in the user's content and constraints, unless a missing reference is essential.

Extract principles rather than reproducing a page: typographic hierarchy, content grouping, navigation behavior, spacing rhythm, density, image treatment, or interaction feedback. Explain why each choice helps this product's users. Use original composition and copy; do not reuse another brand's identity or assets without permission. Verify asset and font licensing before incorporating them.

## Make the direction concrete

Include in the design brief:

- Audience, primary task, brand character, and a concise visual direction with concrete implications. For example, an equipment inventory tool might use compact rows, restrained status colors, tabular numerals, and persistent filters.
- Reference observations and the decisions they inform, including what does not fit this product.
- Typography roles, readable type sizes, spacing rhythm, content width, density, palette, borders, radii, and interaction states. Use fonts and assets actually available to the project.
- A representative screen or mockup using realistic names, labels, and content lengths. For a substantial new interface, make this reviewable before repeating the direction across screens; preserve existing approval or delegated design authority.

If the user has delegated visual choices, choose and explain a direction without adding an approval gate. Ask only when a missing choice materially changes the product or conflicts with the brand.

## Avoid a generic default

Do not automatically build every product as a centered slogan, gradient hero, pill badge, three feature cards, and large call-to-action. Do not force a dashboard into equal cards when rows, a table, or a split view better support the work. Gradients, cards, large type, and rounded corners are valid when the content and direction justify them; a ban on individual styles does not produce a distinctive design.

Create character through composition, typography, useful content, imagery, and consistent details. Avoid decorative charts, invented customer logos, fake testimonials, and unsupported metrics. Match icons and motion to meaningful actions; respect reduced-motion preferences.

## Verify the result

Inspect the rendered representative screen at desktop and narrow mobile widths when tools permit. Check hierarchy, alignment, spacing, text wrapping, content density, image crops, and state consistency against the chosen direction. Retain keyboard, focus, and contrast checks. Record the actual viewport and evidence, fix visible issues, and label anything unverified. A checklist pass cannot prove that a design looks human-made; report concrete decisions and observations instead.
